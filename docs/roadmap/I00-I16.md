# Roadmap I00 → I16

| Iteration | Outcome |
|---|---|
| I00 | Repository foundation, truth model, C4, ADRs, DoD |
| I01 | Card domain model, state machines and Platform SDK contract baseline |
| I02 | Merchant → Acquirer → Scheme → Issuer → Authorization using SDK conventions |
| I03 | Synthetic CB/Visa/Mastercard simulators + Java Platform SDK v1 foundations |
| I04 | Capture and reversal |
| I05 | Kafka, Transactional Outbox, Inbox/DLQ |
| I06 | Ledger and financial posting invariants |
| I07 | Clearing positions and exceptions |
| I08 | Settlement and failure handling |
| I09 | Reconciliation and authoritative inquiry |
| I10 | Refund, chargeback and dispute |
| I11 | Fraud/risk rules |
| I12 | OAuth2/OIDC, Keycloak, Gravitee boundary, mTLS, OpenAPI/AsyncAPI |
| I13 | Observability, SLI/SLO, business KPIs |
| I14 | OpenShift/Kubernetes packaging, Argo CD/GitOps and CI/CD portability |
| I15 | Chaos/resilience + local Kind multi-cluster |
| I16 | Enterprise reference, HA/PRA, DORA, IBM Cloud/Axway/GitLab projections, final demo |

## Sequencing rule

Correctness before scale:

```text
domain correctness
-> financial invariants
-> eventing
-> reconciliation
-> security
-> observability
-> platform
-> resilience
-> multi-cluster
```


## Technology enablement gates

```text
I01-I02  Java + PostgreSQL + Platform SDK baseline
I03-I04  Scheme simulators + SDK v1
I05      Kafka / Outbox / Inbox
I12      Keycloak + API security + Gravitee boundary
I13      OpenTelemetry + Prometheus + Grafana
I14      OpenShift-compatible packaging + Argo CD
I15      Kind mgmt + region-a + region-b
I16      IBM Cloud / Axway / GitLab compatibility projections
```

Rule: deploy a product only when it proves a useful architectural capability.
